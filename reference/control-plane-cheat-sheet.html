Session 3 · Operate

The control plane

The model proposes an action. The control plane decides whether and how the world changes—and preserves enough truth to recover when the answer disappears.

RequestWhat is being asked?
PolicyAllow, ask, or refuse?
ActionWhat actually ran?
ObservationWhat came back?
EventWhat survived on disk?
ReconcileWhat does the world prove?

The key distinction: “the tool did not answer” is a fact about the observation channel. It is not evidence that the action did not happen.

When resuming

Do not guess

  1. Find the durable intent and stable request ID.
  2. Inspect evidence outside the model’s story.
  3. Record ok, failed, or in_doubt.
  4. Retry only when replay is safe and adds evidence.
Before acting

Make recovery possible

  • Record intent before the side effect.
  • Give the intent one ID that survives retries.
  • Keep complete output as an artifact; return a bounded observation.
  • Ask for approval at the consequential action, not just at plan time.
StatusWhat it meansWhat happens next
okIndependent evidence shows the intended effect landed.Record the evidence and continue.
failedEvidence shows the intended effect did not land.Retry only if the result says replay is safe.
in_doubtEvidence cannot settle whether the effect landed.Stop, reconcile further, compensate, or escalate.
refusedPolicy blocked the action deliberately.Follow the named alternative; do not retry the wall.
pendingThe action is waiting for a decision or approval.Preserve the request; do not silently execute it.
Jack’s Project 1 crash window

mkdir succeeds; writeFile never happens

The session directory exists, but the evidence record does not. Retrying with the same sessionId is refused because the directory already exists. Directory existence is therefore not proof that record creation succeeded.

Stable request ID: the logical sessionId. Evidence: a present, parseable meta.json containing the fixed snapshot. Missing control: reconciliation or an atomic commit strategy.
