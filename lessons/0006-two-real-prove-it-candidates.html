Prove-It task selection

Two real candidates

Both are unfinished software work found in active repositories. One is the cleaner learning task; the other carries more consequence and more scope.

Candidate 1 · Screened out

Invoice-ledger reconciliation

Build the deferred v2 feature in Comprendo's invoicing tool: compute the ledger summary from the invoice entries that are already the source of truth.

Observable result

Given a valid project ledger, the tool regenerates invoice count, total billed and last invoice from canonical entries; changes nothing outside the Summary block; and produces the same file on a second run.

Independent checks

  • Hourly and deliverable ledger fixtures produce known totals.
  • Draft, tax, duplicate-period and malformed-entry cases follow operator-owned policy.
  • A second run is byte-identical.
  • Invoice history and human notes are unchanged.

Likely reward hacks

Hard-code the sample, count drafts, silently skip malformed money, or rewrite the whole file while producing the right three numbers.

Why it is weak for Jack

Jack is the only operator, already reviews the ledger, and can cheaply reverse an error. Its oracle is excellent, but its real consequence is low. This belongs in the inner loop, not a three-week consequential delegation.

Candidate 2 · Selected

GAiDFLY trusted submission record

Build a bounded data/API slice of Phase 2: create a submission record whose provenance, transcript and visibility remain trustworthy.

Observable result

When a student submits an assignment-linked session, it retains the exact assignment and attached reading used; its transcript cannot be rewritten; only that student and the owning classroom's faculty can retrieve it; unsubmitted practice stays private.

Independent checks

  • Edit the assignment after starting a session; the old session remains unchanged.
  • Attempt to rewrite a submitted transcript; the server refuses.
  • Cross-student and cross-classroom retrieval fails.
  • An existing database upgrades without losing records.
  • The existing unsubmitted-session privacy test remains green and protected.

Likely reward hacks

Snapshot only an ID, reload live assignment text during debrief, guard the UI but leave the API open, or pass on a fresh database while breaking upgrades.

Decision test

If the course disappeared tomorrow, which task would you still pay a coding agent to build this month?

That answer determines whether either task is genuinely yours. If the answer is “neither,” keep looking rather than manufacturing a demonstration.
