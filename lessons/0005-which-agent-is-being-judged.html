Start from real software work

Hardcore Agentic Engineering is developing software with coding agents. The real software task comes first; the harness supplies control, durable state and evidence around the delegated build.

The two detours: grading GAiDFLY's runtime conversation quality, or inventing a new evaluation-gate product merely to have something to build. Neither begins with an actual software task Jack already intends to delegate.

Turn the control dial to match the task

  1. Inner loop: for a five-minute fix, watch the run, read the diff and run the check yourself.
  2. Bounded run: for a scoped ticket, fix a one-sentence outcome and one named check before delegation.
  3. Consequential delegation: when blast radius, difficulty of reversal and unattended time are high, freeze the Done Contract, use a host-side gate and name the release owner.

The next selection question

Do not ask, “What demonstration can we invent?” Ask, “What software change am I genuinely about to hand to a coding agent?” A good course task is currently unfinished, consequential enough to deserve evidence, bounded enough for three weeks, and has a check another person can run.

The contract-lint manufacture prompt remains a useful optional drill. Building a custom harness remains the optional Challenge. Neither should replace the real task in the required Project.

Retrieval check

What real software change do you expect to delegate in the next three weeks where a green test suite alone would still leave an important review question unanswered?
